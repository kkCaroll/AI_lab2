# 后续计划

试点已冻结设置并启动 500 题全量运行，后续工作分五个阶段。

## 1 全量运行与完整性校验

全量运行由 run_all.py 顺序执行六种方法，Direct 已完成 450 题，其余方法依次进行，试点已完成的 50 题按 unique_id 复用。预计 Debate 与自研系统的耗时最长，Debate 每题约 18 秒，自研系统每题约 20 秒，八并发下整体约两小时。

运行结束后的校验项

1. 六份 JSONL 各含 500 条记录，unique_id 无重复且与数据集全集一致。
2. 失败类型分别计数，若某方法 request_failed 非零，检查对应题号并单题续跑。
3. max_tokens 为 8192 下是否仍有截断，按输出长度接近上限的记录抽样检查。
4. 自研系统平均每题 token 不超过 6500，并统计单题超过 6500 的题数占比。

若运行中断，run_eval.py 按 unique_id 去重续跑，不重复计费。

## 2 汇总与统计

用 summarize.py 以 500 为分母生成总体与分难度准确率、平均输入输出 token，写入 RECORD 目录。用 analyze_mas.py 统计难度路由分布、两个 Skill 的调用次数、修订轮数、各路由的平均 token 与调用次数。另外补充三项分析

1. 自研系统与 CoT 的逐题分歧，逐条人工核对，区分抽取误判与推理错误。
2. 各方法错题的难度分布与题目类型分布，定位多智能体协作在哪些题型上有效。
3. 准确率与平均 token 的联合视角，给出单位 token 的准确率增益。

产出文件为 RECORD/汇总表.csv、RECORD/系统统计.md、RECORD/错题分析.md，图表视需要补充。
