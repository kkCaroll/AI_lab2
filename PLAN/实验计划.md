# 实验二 多智能体系统设计与评测 实验计划

## 1 目标与约束

在统一模型 qwen3.7-flash、统一数据 MATH-500 全量 500 题、统一解码参数与统一答案抽取的前提下，实现五种规定方法与一种自研多智能体系统，统计总体与分难度准确率以及平均每题输入、输出 token，并据此分析多智能体协作的收益与成本。

硬性约束

1. 六种方法使用同一模型，不得替换为其他模型。
2. 提示词、对话记忆与日志回放中不得出现 answer 与 solution，评分只在模型返回后进行。
3. 六种方法共用同一套答案抽取与规范化规则。
4. 自研系统至少包含两个职责不同的 Agent，后序 Agent 必须读取前序输出并据此改变推理或答案。
5. 自研系统平均每题总 token 不超过 6500。
6. 自研系统至少实现两个可复用推理 Skill，并由 Agent 在解题过程中调用。
7. 失败、空答案、抽取失败单独计数，不从 500 的分母中剔除。

## 2 数据与评测协议

### 2.1 数据

MATH-500 全量 500 题，字段 problem、solution、answer、subject、level、unique_id。难度分布为 L1 43 题、L2 90 题、L3 105 题、L4 128 题、L5 134 题。题目文本平均约 196 字符，参考解答平均约 531 字符。

加载后固定顺序并缓存到 data/，训练与提示词开发过程中只使用 problem 字段。answer 与 solution 仅在评分脚本中读取。

### 2.2 答案抽取与规范化

抽取函数 extract.py 对六种方法完全一致，实现顺序如下

1. 取最后一个平衡花括号的 \boxed{...}，支持嵌套。
2. 若无 boxed，取最后一个独立成行的公式，或 answer is 之后的内容。
3. 去除首尾空白、美元符号、句末标点与句尾多余文字。

规范化规则

1. 删除空白、\left、\right、\displaystyle、\,、\;、\!。
2. \dfrac 与 \tfrac 统一为 \frac，\cdot 与 \times 统一为 \times，^{\circ} 统一为度符号。
3. 千分位逗号在纯数字中删除，其余逗号保留。
4. 分数、根式、区间与集合保持 LaTeX 形式，不做数值近似。

等价判定

1. 规范化字符串相等即判对。
2. 字符串不等时用 sympy 解析两侧表达式，若两者差化简为 0 则判对。
3. 解析失败时退回字符串比较，不判对。

抽取函数先在 20 题上人工核对，统计误判类型后冻结，全量运行期间不再修改。

### 2.3 评分与统计

每题记录 correct、input_tokens、output_tokens、calls、failure_type、latency。准确率等于判对题数除以 500；分难度准确率的分母为该难度题数。token 按题累加后除以 500，得到平均每题输入与输出 token，总 token 为两者之和。汇总脚本同时输出 CSV 与 Markdown 表格。

### 2.4 运行记录与失败处理

每次调用保存原始返回、提示词版本与解码参数，写入 results/raw/{method}.jsonl，按 unique_id 去重，支持断点续跑。请求失败重试 3 次，仍失败记为 request_failed；返回为空记为 empty_output；抽不出答案记为 extract_failed；三类均计入分母。

## 3 六种方法设计

| 方法 | 调用次数 | 核心提示词要求 | 说明 |
|---|---|---|---|
| Direct | 1 | 只给题面与答案格式要求，直接给最终答案 | 不要求过程 |
| CoT | 1 | 先分步推理，再在末行给 \boxed{} | 单次调用 |
| Self-Consistency | 5 | 与 CoT 相同的提示词，独立采样 5 次 | 规范化答案多数票，平票取出现最早者 |
| Self-Refine | 2 至 7 | 初答，自评，按自评修改，最多 3 轮反馈 | 自评认为无需修改则提前停止，每轮反馈为一次自评加一次修改 |
| Multi-Agent Debate | 12 | 3 个 Agent 4 轮，首轮独立作答，之后阅读他人上一轮解答 | 对最后一轮抽取结果多数票 |
| 自研系统 | 2 至 8 | 见第 4 节 | 难度路由与置信度终止 |

所有方法共用同一 system prompt 片段与答案格式要求，仅在任务指令上不同。讲义只要求 temperature 与 top_p 在六种方法间保持一致并写入报告，未规定具体数值，本实验固定 temperature 0.7、top_p 0.8，enable_thinking 为 False。该取值不为 0，保证 Self-Consistency 的五次采样存在差异。

小样本冒烟测试得到的每题平均总 token 为 Direct 约 0.14k、CoT 约 0.82k、Self-Consistency 约 4.5k、Self-Refine 约 6.1k、Debate 约 30.9k。Debate 的输入随轮数线性增长，每轮需向三个智能体展示三份完整解答，因此远高于其他方法。自研系统有 6500 的硬预算，设计上不得照搬该传阅方式，应传摘要或抽取答案。全量 500 题的 token 总量按上述均值估计约 21M，实际以试点为准。

## 4 自研系统设计

### 4.1 总体结构

系统按题目难度选择参与角色，控制调用次数与 token。

```
题目
  │
  ▼
Planner（仅 medium 与 hard 调用）
  │  子目标、难度估计、所需 Skill
  ▼
Solver ──► Verifier ──► 通过且置信度达标 ──► 最终答案
             │
             ▼ 不通过或置信度不足
          Reviser ──► Verifier 复审（最多两轮）
```

### 4.2 Agent 职责

| Agent | 输入 | 输出 | 下游如何使用 |
|---|---|---|---|
| Planner | 题面 | 难度估计、子目标列表、Skill 调用建议 | Solver 按子目标组织推理 |
| Solver | 题面、Planner 输出（若有） | 完整解答、\boxed{} 答案、自评置信度 | Verifier 逐条核查 |
| Verifier | 题面、Solver 解答（不含标准答案） | 判定 pass 或 fail、置信度 0 到 100、错误位置、建议答案 | fail 或低置信度时触发 Reviser |
| Reviser | 题面、原解答、Verifier 意见 | 修订解答与最终答案 | 交给 Verifier 复审 |

### 4.3 难度路由

Planner 由题面估计难度为 easy、medium、hard，不使用数据集 level 字段参与路由，level 仅用于结果分层统计。难度路由只作用于自研系统，五种对照方法的调用方式与数据集难度无关，因此该选择不影响对照之间的可比性。

| 路由 | 触发条件 | 参与 Agent | 每题预算上限 |
|---|---|---|---|
| 简单 | easy | Solver | 1500 |
| 中等 | medium | Solver、Verifier | 3000 |
| 困难 | hard | Planner、Solver、Verifier、按需 Reviser | 6500 |

### 4.4 提前终止

1. Verifier 判定 pass 且置信度不低于 75 时立即结束。
2. 两轮修订后抽取答案不变时结束。
3. 每题累计 token 达到预算上限时跳过剩余 Skill 与修订，直接输出当前答案。
4. 每题最多 8 次模型调用。

### 4.5 推理 Skill

Skill 以结构化标记 `[[SKILL: 名称 | 参数]]` 在 Agent 输出中请求，由调度器执行并回填结果，提示词模板与调用函数独立于具体方法，可复用于其他 Agent。

| Skill | 功能 | 主要调用者 |
|---|---|---|
| decompose | 将题目拆为可独立求解的子目标 | Planner |
| substitute_check | 将候选答案代回原题条件做数值或代数检验 | Verifier |
| alternative_method | 用与 Solver 不同的方法重算关键步骤 | Verifier，仅 hard |

### 4.6 token 预算核算

按难度分布估算，easy 133 题每题不超过 1.5k，medium 105 题每题不超过 3k，hard 262 题每题不超过 6.5k，加权平均上限约 4.4k，留有约 30% 余量。试点阶段按实测均值调整阈值，若超出 6500 则先删减 alternative_method 与第二轮复审。

## 5 代码结构

```
code/
  common/  config.py llm.py data.py extract.py scorer.py runner.py
  methods/ direct.py cot.py self_consistency.py self_refine.py debate.py
  mas/     system.py agents.py skills.py prompts.py
scripts/
  check_conn.py run_eval.py run_all.py demo_one.py
data/      缓存数据，不提交
results/   原始输出与汇总表
```

run_eval.py 接受方法名、并发数、题号范围与是否续跑。demo_one.py 打印指定题目的每个 Agent 输入输出、传递内容与最终答案，用于现场验收。

## 6 实施步骤

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| M1 | 数据加载、抽取、评分、运行器 | 20 题人工核对抽取正确 |
| M2 | 五种对照方法 | 每种方法 5 题试跑无报错，token 记录完整 |
| M3 | 50 题分层试点 | 得到各方法 token 与准确率初值，冻结提示词 |
| M4 | 自研系统与三个 Skill | 单题演示各 Agent 输出与传递内容，平均 token 低于 6500 |
| M5 | 全量 500 题六种方法 | 六份 JSONL 完整，失败单独计数，汇总表生成 |
| M6 | 分析与报告 | LaTeX 报告五部分完成，结构图与结果表就位 |

试点使用 L3 至 L5 各 10 题的开发子集调整提示词，该子集仍计入最终 500 题结果，报告注明提示词仅在开发子集上迭代。

## 7 结果产出与报告

RECORD 存放汇总表、分难度表、token 表与图表。报告使用 LaTeX，结构如下

1. 实验原理，含系统结构图，用 TikZ 绘制。
2. 实验设置，模型、数据集、temperature、top_p、enable_thinking、采样次数、Debate 人数与轮数、自研路由阈值。
3. 实验结果，八列统一表。
4. 结果分析，与五种对照的机制差异、各难度表现、准确率与 token 的联合变化。
5. 实验总结，最难的约束与为此删减的调用。

## 8 风险与应对

| 风险 | 应对 |
|---|---|
| 抽取误判影响准确率 | 统一函数、人工抽查、保留原始输出可复核 |
| 接口限流或超时 | 并发 4 至 8、指数退避重试、断点续跑 |
| 自研系统超 token 预算 | 预算闸门、按难度设上限、试点后删减调用 |
| 提示词误含答案 | 数据读取层只暴露 problem，评分单独进程读取 answer |
| 现场演示失败 | demo_one.py 支持单题离线重放已保存的中间输出 |
